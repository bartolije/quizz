# Session 4 — Boucle de jeu live (MCQ + timer)

## Contexte

S1 à S3 terminées : lobby temps réel, vues host `/host/control` + `/host/display`,
démarrage synchronisé (`session_status_changed`). On construit maintenant la
**boucle de jeu temps réel** pour les questions à choix multiples (MCQ).

Toujours **en mémoire** : pas de DB. Un quiz de démo est seedé côté serveur ; la
persistance et l'éditeur viennent en S8. Ne pas casser le flow join/rejoin (S2)
ni les vues host (S3).

### Décisions transverses actées (valables S4→S8)

- **Rythme : host-paced.** Le host lance chaque question. Une question se ferme
  **automatiquement** à la fin du timer **OU** dès que tous les participants
  connectés ont répondu (le premier des deux).
- **Écran téléphone (MCQ) :** la TV (`/host/display`) porte **l'énoncé + les
  choix**. Le téléphone n'affiche que des **boutons A/B/C/D colorés**, chacun
  portant le **texte de sa réponse** — mais **pas l'énoncé** (il faut regarder la
  TV pour la question).
- **Scoring : vitesse linéaire** 1000→0 (`calculateScore` déjà dans
  `shared/scoring.ts`). Pas de streak.

---

## Objectif de S4

À la fin :

1. Le host démarre le quiz (`host_start_quiz`, déjà fait) puis **lance la
   première question** (`host_next_question`).
2. `question_started` diffusé → la TV affiche énoncé + choix, les tél affichent
   les boutons.
3. Le **timer** tourne, synchronisé (basé sur `startedAt` serveur).
4. Les participants tapent un bouton → `submit_answer` (une seule réponse retenue).
5. Le host voit le compteur **« X / Y ont répondu »** en direct (`answer_received`).
6. La question se ferme (timer écoulé **ou** tous répondu) → `question_ended` :
   révélation de la bonne réponse + **répartition des réponses** sur la TV +
   score perso sur le tél.
7. Le host enchaîne (`host_next_question`) jusqu'à la dernière, puis fin du quiz.

## Quiz de démo (seed mémoire)

- `src/seed-quiz.ts` : un `Quiz` avec ~5 questions MCQ (`text`, `choices[4]`,
  `correctAnswers`, `timeLimit`).
- `host_start_quiz` (ou `createSession`) charge ce quiz dans `session.quiz`
  (champ déjà réservé dans `state.ts`, aujourd'hui `null`).
- Exposer l'accès via `getQuiz(session)` pour que la bascule vers la DB en S8
  ne touche qu'un point.

## Contrat d'events

Réutilise : `host_start_quiz`, `host_next_question`, `submit_answer`,
`question_started`, `question_ended`, `answer_received`.

**Ajout à `shared` (`question_ended`)** — la répartition des réponses pour la TV :

```
question_ended.payload += distribution: { value: string; count: number }[]
```

Les participants ignorent ce champ ; la TV l'utilise pour le bar chart. Rebuild
`shared` après l'ajout (résolution via `dist/`).

## Comportement serveur

État ajouté à `SessionState` : `answers: Map<participantId, { value, submittedAt }>`
(réponses de la question courante) + handle du timer.

- **`host_start_quiz`** : `status = 'running'`, broadcast `session_status_changed`
  (déjà en place). N'ouvre **pas** encore de question.
- **`host_next_question`** :
  - garde-fou : ignoré si une question est déjà ouverte (`questionStartedAt != null`).
  - avance `currentQuestionIndex` (première fois → 0) ; si on dépasse le nombre de
    questions → **fin** (`status = 'ended'`, leaderboard final — détail en S5).
  - réinitialise `answers`, `questionStartedAt = Date.now()`.
  - arme `setTimeout(timeLimit)` → `closeQuestion`.
  - broadcast `question_started { question: QuestionPublic (sans correctAnswers), startedAt }`.
- **`submit_answer`** :
  - rejeté si aucune question ouverte ou si le participant a déjà répondu
    (idempotent — la 1ʳᵉ réponse compte ; « changer d'avis » traité en S7).
  - enregistre `{ participantId, value, submittedAt: Date.now() }`.
  - emit `answer_received` à la room host (`answeredCount` / `totalCount`).
  - si `answeredCount === participants connectés` → `clearTimeout` + `closeQuestion`
    (fin anticipée).
- **`closeQuestion`** :
  - `questionStartedAt = null` (ferme).
  - pour chaque réponse : `isCorrect = value ∈ correctAnswers` ;
    `score = isCorrect ? calculateScore(timeLimit, elapsed) : 0` avec
    `elapsed = (submittedAt - startedAt) / 1000` ; cumule `participant.score`.
  - calcule la `distribution` (count par choix).
  - calcule le leaderboard (`getLeaderboard` — basique en S4, raffiné en S5).
  - emit `question_ended` **personnalisé par participant** (`myAnswer` / `myScore`
    / `myDelta`) + `correctAnswers` + `distribution` + `scores`.
  - emit aussi au host (`myAnswer = null`) pour la révélation TV.

---

## Comportement client

- **Store** : ajouter `currentQuestion`, `questionStartedAt`, `lastResult`
  (`myScore` / `myDelta` / `correct`), `answeredCount` / `totalCount` (host).
- **Listeners** : `question_started`, `question_ended`, `answer_received`.
- **Participant (mobile)** :
  - vue `question` : 4 boutons couleur (rouge / bleu / jaune / vert, formes
    triangle / losange / rond / carré), **texte de la réponse sur chaque bouton**,
    énoncé NON affiché. Anneau de timer. Tap → `submit_answer` puis « Réponse
    envoyée, en attente… » ; boutons désactivés après le tap.
  - vue `answer` (après `question_ended`) : « Correct +850 » ou « Raté », score
    cumulé.
- **Host control** : bouton « Lancer la question » / « Question suivante »,
  compteur X / Y, aperçu de la question courante.
- **Host display (TV)** :
  - pendant la question : énoncé en grand, les 4 choix colorés en grille, timer,
    compteur de réponses.
  - après : surbrillance de la bonne réponse + bar chart de la `distribution`.

---

## Timer synchronisé

`question_started.startedAt` = horloge serveur. Pour éviter le décalage
d'horloge client, le client traite **la réception** comme `t0` et décompte
`timeLimit`. La valeur serveur reste la référence pour la reconnexion (S7, via
`session_restored.timeElapsed`).

---

## Design

Couleurs / formes façon Kahoot. Boutons plein écran sur mobile (zones de tap
larges). TV : contraste fort, gros caractères, lisible à 4 m.

---

## Checklist de validation

1. Le host lance Q1 → la TV affiche énoncé + choix, 2 tél affichent les boutons.
2. Un tél répond → le host voit « 1 / 2 ».
3. Les 2 répondent → la question se ferme **immédiatement** (avant le timer).
4. Laisser le timer expirer sans répondre → la question se ferme, score 0.
5. Bonne réponse rapide > bonne réponse lente (vérifier les scores).
6. `question_ended` montre la bonne réponse + la distribution correcte sur la TV.
7. Enchaîner toutes les questions → fin du quiz (`status = 'ended'`).

---

## Ce qu'on ne fait PAS en S4

- Pas de leaderboard / podium soigné (S5).
- Pas de saisie libre / numérique (S6).
- Pas de reconnexion en pleine question (S7).
- Pas de DB ni d'éditeur (S8).

## Décisions à trancher au démarrage de S4

- `timeLimit` par défaut (ex. 20 s).

- Forme exacte des boutons (couleurs + formes Kahoot, ou plus neutre).
