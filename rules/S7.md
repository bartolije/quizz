# Session 7 — Robustesse, reconnexion en jeu, contrôles host

## Contexte

C'est **LA priorité du projet** (stabilité WebSocket). Jusqu'ici la reconnexion
restaure le lobby (S2) mais **pas l'état d'une question en cours**. S7 rend la
reconnexion transparente **en plein jeu** et durcit les cas limites.

---

## Objectif de S7

1. Un participant qui perd le réseau 2-3 s pendant une question le **retrouve** :
   même question, **temps restant correct**, peut encore répondre s'il n'a pas
   répondu et qu'il reste du temps.
2. `session_restored` renvoie `currentQuestion` + `timeElapsed` **réels**
   (aujourd'hui `null` / 0).
3. Le host qui rafraîchit `/host/control` **reprend la main** avec l'état courant
   (question en cours, compteur).
4. Politique de **late-join** définie et implémentée.
5. **Contrôles host** : `host_end_quiz` (fin anticipée → podium), garde-fous,
   éventuellement passer / sauter.
6. **Réponses tardives** ignorées proprement, pas de double comptage.

---

## Contrat d'events

- `session_restored` existe déjà avec `currentQuestion` / `timeElapsed` /
  `myScore` / `myRank` → S7 les **remplit vraiment**.
- `host_end_quiz` : **pas encore de handler** → l'ajouter (`status = 'ended'` +
  `leaderboard_update { final: true }`).
- Restauration de l'état **host** à la reconnexion : réutiliser `session_joined`
  enrichi (avec la question courante) ou un nouvel event `host_state`. À trancher.

---

## Serveur

- **`handleRejoin`** : si une question est ouverte → `currentQuestion =
  QuestionPublic`, `timeElapsed = (now - startedAt) / 1000`, et indiquer si le
  participant **a déjà répondu** (pour figer son UI).
- **Réponses** : rejet si question fermée ; « déjà répondu » → ignoré (ou
  autoriser le changement avant fermeture — à trancher).
- **Late-join** (`join_session` alors que `status = 'running'`) :
  - proposé : autorisé en **spectateur** jusqu'à la prochaine question (score 0 sur
    la question en cours), rejoint pleinement à la suivante.
  - alternatives : bloqué, ou peut répondre à la question en cours avec le temps
    restant. À trancher.
- **Reconnexion host** : `handleHostJoin` renvoie aussi l'état de la question
  courante (énoncé, compteur, temps).
- **Host déconnecté en pleine question** : le timer serveur **continue** (déjà
  côté serveur), la question se ferme normalement.
- **Tous déconnectés** : la question se ferme au timer ; nettoyage.
- **TTL token** (`SESSION_TOKEN_TTL_MS = 30 s`) respecté pour le cleanup des
  déconnectés.

---

## Client

- À l'event `connect`, le client ré-émet `rejoin_session` (déjà en place). Sur
  `session_restored` : si `currentQuestion != null` → aller **directement** en vue
  `question` avec `timer = timeLimit - timeElapsed` ; si déjà répondu → vue « en
  attente ».
- Indicateur réseau discret (« reconnexion en cours… »).
- Host : reprise transparente.

---

## Checklist de validation (le cœur du projet)

1. Répondre, couper le réseau 3 s, revenir → état question conservé, réponse
   conservée.
2. Couper le réseau **avant** de répondre, revenir avec du temps restant → peut
   répondre.
3. Couper pendant la révélation → revient sur le classement / la révélation.
4. **Refresh complet** du tél en pleine question → rejoin via token → reprise.
5. Refresh `/host/control` en pleine question → reprise avec compteur.
6. `host_end_quiz` au milieu → podium immédiat.
7. Late-join pendant une question → comportement conforme à la politique choisie.
8. 15-20 participants, coupures simultanées → pas de crash, états cohérents.
