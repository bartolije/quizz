# Session 9 — Déploiement : le jeu sur Vercel, le serveur sur Railway

> **Pour qui ?** Ce guide est écrit pas à pas, sans pré-requis technique.
> Tu vas surtout **cliquer dans deux sites web** (Vercel et Railway) et **copier-coller
> une adresse**. Suis les étapes dans l'ordre. Compte ~20-30 minutes la première fois.

---

## 1. Comprendre en 30 secondes (le « quoi va où »)

LYA QUIZ a **deux morceaux** qui vivent à deux endroits différents :

| Morceau | C'est quoi | Où il va | Pourquoi |
|---|---|---|---|
| **Le jeu** (ce que voient le host et les téléphones) | Un site web | **Vercel** | Vercel héberge les sites web gratuitement et très bien. |
| **Le serveur** (le temps réel : qui répond, les scores) | Un programme qui tourne en continu | **Railway** | Le temps réel a besoin d'un programme **toujours allumé**. Vercel ne sait pas faire ça, Railway oui. |

Les deux discutent ensemble par Internet. Le jeu (Vercel) a besoin de connaître **l'adresse du serveur** (Railway). C'est tout le secret de ce guide.

**Conséquence importante sur l'ordre :** on déploie **d'abord le serveur (Railway)** pour récupérer son adresse, **ensuite le jeu (Vercel)** en lui donnant cette adresse.

---

## 3. (Recommandé) Tester en local AVANT de déployer

Pour vérifier que tout marche sur ton Mac avant de mettre en ligne :

```bash
cd ~/Development/quizz
npm install        # la première fois seulement
npm run dev        # démarre le serveur (:3001) ET le jeu (:5173)
```

Puis sur ton Mac, ouvre dans le navigateur :
- **Écran de contrôle** : http://localhost:5173/host/control
- **Écran TV** (2ᵉ fenêtre) : http://localhost:5173/host/display

Sur ton **téléphone connecté au même WiFi**, ouvre l'adresse « Network » affichée dans le terminal (genre `http://192.168.1.89:5173`), ou **scanne le QR code** affiché sur l'écran de contrôle.

> ⚠️ **Si ça ne démarre pas** : un autre programme occupe peut-être le port 3001 ou 5173.
> Lance avec un autre port serveur : `PORT=3010 npm run dev:server` dans un terminal,
> et le jeu dans un autre : `npm run dev:client`.

Déroule un quiz complet (Démarrer → Lancer la question → répondre sur le téléphone → la réponse s'affiche). Si ça marche en local, on passe au déploiement.

## 4. Déployer le SERVEUR sur Railway (à faire en premier)

1. Va sur **railway.app** et connecte-toi.
2. Clique **New Project** → **Deploy from GitHub repo**.
3. Choisis le dépôt **`bartolije/quizz`**. (Si Railway ne le voit pas, clique « Configure GitHub App » et autorise l'accès au repo.)
4. Railway lit tout seul le fichier `railway.json` et commence à **construire** (build) puis **lancer** (deploy) le serveur. Laisse-le faire (2-4 min).
5. **Rends le serveur accessible depuis Internet :**
   - Ouvre ton service → onglet **Settings** → section **Networking**.
   - Clique **Generate Domain**.
   - Railway crée une adresse du type **`https://quizz-production-xxxx.up.railway.app`**.
   - 📋 **Copie cette adresse** — c'est l'adresse du serveur, on en a besoin à l'étape suivante.
6. **Vérifie que le serveur est en vie :** ouvre dans ton navigateur cette adresse suivie de `/health` :
   ```
   https://quizz-production-xxxx.up.railway.app/health
   ```
   Tu dois voir : `{"status":"ok","sessions":0}` ✅
   Si tu vois ça, le serveur tourne. Sinon → va voir la section **Dépannage**.

> 💡 Tu n'as **aucune variable à configurer** côté Railway. Le serveur s'adapte tout seul au port que Railway lui donne.

---

## 5. Déployer le JEU sur Vercel

1. Va sur **vercel.com** et connecte-toi.
2. Clique **Add New… → Project** → importe le dépôt **`bartolije/quizz`**.
3. Vercel lit tout seul le fichier `vercel.json` (commande de build, dossier de sortie). **Ne change rien** dans les réglages détectés.
4. **AVANT de cliquer Deploy**, ouvre **Environment Variables** et ajoute :
   - **Name** : `VITE_SERVER_URL`
   - **Value** : l'adresse du serveur copiée à l'étape 4.5 (ex. `https://quizz-production-xxxx.up.railway.app`)
   - ⚠️ **Sans slash `/` à la fin.**
5. Clique **Deploy**. Attends 1-2 min.
6. Vercel te donne l'adresse du jeu, du type **`https://quizz-xxxx.vercel.app`**. 🎉

> ⚠️ **Le piège n°1** : si tu oublies `VITE_SERVER_URL` (ou si tu la mets après coup), le jeu ne trouvera pas le serveur. La variable est lue **au moment du build** : si tu la changes, il faut **redéployer** (Vercel → Deployments → bouton ⋯ → **Redeploy**).

---

## 6. Tester que tout marche (en ligne)

1. Sur ton **Mac**, ouvre **`https://quizz-xxxx.vercel.app/host/control`**.
   → Un **PIN** et un **QR code** s'affichent. ✅
2. Sur ta **TV / un 2ᵉ écran**, ouvre **`https://quizz-xxxx.vercel.app/host/display`** (sur le même navigateur/profil il retrouve la session ; sinon ajoute `?session=…`, voir note plus bas).
3. Avec ton **téléphone (4G ou n'importe quel WiFi, plus besoin du même réseau !)** : scanne le QR code, ou va sur `https://quizz-xxxx.vercel.app/join` et tape le PIN.
4. Mets un pseudo → tu apparais dans la liste sur l'écran de contrôle **et** sur la TV. ✅
5. Sur le Mac : **Démarrer le quiz** → **Lancer la première question**.
   - La TV affiche la question + les 4 choix colorés + le timer.
   - Le téléphone affiche les 4 boutons de réponse.
6. Réponds sur le téléphone → tu vois « Correct / Raté » + ton score. La TV montre la bonne réponse. ✅
7. Enchaîne avec **Question suivante** jusqu'au classement final.

**Si les 7 étapes passent : c'est déployé et fonctionnel. 🏆**

## 7. Quoi regarder / Dépannage

### Où voir ce qui se passe

| Quoi | Où |
|---|---|
| Le serveur démarre-t-il ? | Railway → ton service → onglet **Deployments** → clique le déploiement → **View Logs**. Tu dois voir `Server listening`. |
| Le serveur répond-il ? | Ouvre `https://…railway.app/health` → doit afficher `{"status":"ok"}`. |
| Le jeu s'est-il construit ? | Vercel → **Deployments** → le dernier doit être **Ready** (vert). |
| Le jeu n'arrive pas à se connecter ? | Sur la page du jeu, ouvre la console du navigateur (touche **F12** → onglet **Console**). Des erreurs `socket`/`connection` = mauvaise `VITE_SERVER_URL` ou serveur éteint. |

### Erreurs fréquentes

| Symptôme | Cause probable | Solution |
|---|---|---|
| Le jeu charge mais « Création de la session… » reste bloqué | `VITE_SERVER_URL` absente, mauvaise, ou avec un `/` final | Corrige la variable dans Vercel → Settings → Environment Variables, puis **Redeploy** le jeu. |
| `/health` ne répond pas / erreur 502 sur Railway | Le serveur n'a pas démarré (build raté, ou pas de carte de paiement) | Regarde les **logs Railway** ; vérifie la facturation. |
| Le QR envoie vers `localhost` | Tu testes encore en local | Normal en local ; en ligne le QR pointe vers l'adresse `vercel.app`. |
| Rafraîchir une page (ex. `/host/control`) donne une erreur 404 | (Ne devrait pas arriver : `vercel.json` gère déjà ça) | Vérifie que `vercel.json` est bien présent à la racine du repo. |

## 8. La suite (au quotidien)

- **Déploiement automatique** : maintenant que c'est branché, **chaque `git push` sur `main`** redéploie tout seul le jeu (Vercel) **et** le serveur (Railway). Tu n'as plus rien à faire.
- **⚠️ Ne redéploie pas pendant une partie en cours** : à chaque déploiement, le serveur redémarre et les **parties en cours sont perdues** (les scores ne sont pas encore sauvegardés en base — ça viendra avec la session S8). Les quiz eux-mêmes sont dans le code, ils ne se perdent pas.
- **Coût** : Vercel = gratuit. Railway ≈ 5 $/mois tant que le serveur tourne.

## 9. Plus tard (optionnel) : ton adresse perso `quizz.jbartoli.fr`

Quand tu voudras une jolie adresse au lieu de `quizz-xxxx.vercel.app` :
1. Vercel → ton projet → **Settings → Domains → Add** → tape `quizz.jbartoli.fr`.
2. Vercel t'affiche **un enregistrement DNS** (un `CNAME`) à ajouter chez l'hébergeur de `jbartoli.fr`.
3. Ajoute-le, attends quelques minutes : le jeu répond sur `quizz.jbartoli.fr`.
4. Le QR code s'adapte tout seul à la nouvelle adresse (rien d'autre à changer).

> Le serveur Railway peut rester sur son adresse `…railway.app` — les joueurs ne la voient jamais.

## Ce que S9 NE fait PAS

- Pas de sauvegarde en base de données (parties/scores en mémoire) — c'est **S8**.
- Pas d'authentification sur les écrans host (n'importe qui avec le lien `/host/control` peut créer une session) — à ajouter si besoin.
- Pas de mise à l'échelle multi-serveurs (un seul serveur Railway, parfait pour 15-30 joueurs internes).
