# Session 6 — Saisie libre & numérique au plus proche

## Contexte

MCQ complet (S4-S5). S6 ajoute les **deux autres types** de question : `free`
(texte) et `closest` (numérique). La logique pure existe **déjà** dans
`shared/scoring.ts` : `isCorrectFreeAnswer`, `normalizeAnswer`, `levenshtein`,
`calculateClosestScore`.

Acté : **closest = tout le monde marque**, dégressif selon la distance.

---

## Objectif de S6

1. Question **`free`** : le tél affiche un **champ texte** (pas de boutons).
   Réponse correcte si elle matche une des bonnes réponses (normalisation +
   Levenshtein ≤ 2). Score vitesse si correct.
2. Question **`closest`** : le tél affiche un **champ numérique**. Score dégressif
   pour **tous** selon `|écart|` (`calculateClosestScore` avec `maxDeviation` =
   max des écarts parmi les réponses de la question). Le plus proche = 1000.
3. **Révélation** adaptée sur la TV pour chaque type.

---

## Contrat d'events

- `submit_answer` accepte déjà `string | number`.
- `question_started.type` pilote le rendu du tél.
- La `distribution` (S4) est peu pertinente pour `free` / `closest`. Ajout
  possible à `shared` pour la révélation, à trancher au démarrage :
  - `closest` : valeur correcte + (option) gagnant `{ pseudo, value }`.
  - `free` : la / les réponses acceptées.

---

## Serveur — `closeQuestion` étendu (selon `type`)

- **`mcq`** : comme S4.
- **`free`** : `isCorrect = isCorrectFreeAnswer(value, correctAnswers)` ; score
  vitesse si correct.
- **`closest`** :
  - parse `value` en nombre ; ignorer / score 0 si non numérique.
  - `maxDeviation = max(|correct - v|)` sur toutes les réponses (> 0).
  - pour chacun : `score = calculateClosestScore(correct, v, maxDeviation)`.
  - pas de bonus vitesse ici (proposé — à confirmer).

---

## Client

- **Participant** : rendu conditionnel sur `currentQuestion.type` :
  - `free` : input texte + bouton Envoyer.
  - `closest` : input numérique (`inputMode="numeric"`) + bouton Envoyer.
- **Révélation** :
  - `free` : « La réponse : Paris (aussi acceptées : …) » + correct / raté.
  - `closest` : « C'était 1969 — tu as dit 1972 (écart 3) → 780 pts ». TV : la
    bonne valeur + le plus proche (gagnant).

---

## Design

Champs larges sur mobile, clavier adapté (numérique pour `closest`). Révélation
TV lisible à distance.

---

## Checklist de validation

1. `free` : « Pâris » accepté pour « paris » (accents / casse). « pariss » accepté
   (Levenshtein). « lyon » refusé.
2. `free` : plusieurs bonnes réponses → n'importe laquelle valide.
3. `closest` : le plus proche = 1000, les autres dégressifs, le plus loin proche
   de 0.
4. `closest` : tous marquent (> 0 sauf le plus loin, selon `maxDeviation`).
5. Un quiz **mixant les 3 types** s'enchaîne sans accroc.

## Ce qu'on ne fait PAS en S6

- Pas de DB / éditeur (S8).

## Décisions à trancher au démarrage de S6

- `closest` : format des nombres (entiers seulement ? décimales ?).
- `free` : afficher les réponses des participants sur la TV (risque de contenu

- `free` : longueur max, normalisation déjà gérée (espaces / accents / tirets).
