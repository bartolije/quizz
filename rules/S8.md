# Session 8 — Persistance (Drizzle + better-sqlite3) & éditeur de quiz admin

## Contexte

Tout tournait en mémoire avec un quiz seedé (S4). S8 **persiste les quizz** en
SQLite (Drizzle) et ajoute l'**UI admin** pour créer / éditer un quiz et le
**lancer dans le salon**. C'est la 2ᵉ priorité produit (la visu admin).

---

## Objectif de S8

1. **Schéma DB** : `quizzes` + `questions` (type, choices, correctAnswers,
   timeLimit, ordre, `mediaUrl?`).
2. **CRUD quizz** via API REST + Drizzle.
3. **Éditeur `/admin`** : lister, créer, éditer un quiz ; ajouter / réordonner /
   supprimer des questions des 3 types ; définir `timeLimit` et bonnes réponses.
4. **« Lancer ce quiz »** → crée une session liée au `quizId` → ouvre
   `/host/control` sur ce quiz (remplace le seed).
5. Les sessions de jeu **chargent leurs questions depuis la DB**.

---

## Stack

`drizzle-orm` + `better-sqlite3` (prévus dès S1). Fichier SQLite local +
migrations Drizzle.

---

## Schéma proposé

- `quizzes(id, title, defaultTimeLimit, createdAt, updatedAt)`
- `questions(id, quizId FK, type, text, choices JSON, correctAnswers JSON,
  timeLimit, order, mediaUrl)`
- (option) `games` / `results` pour l'historique des parties — à trancher.

---

## API

- `GET / POST / PUT / DELETE /api/quizzes`, `/api/quizzes/:id/questions` …
- `POST /api/sessions { quizId }` → session **liée** (étend l'existant).

---

## Client admin

- `/admin` : liste des quizz (titre, nb de questions, dernier lancement), bouton
  Créer.
- éditeur : titre, `timeLimit` par défaut, liste de questions (drag-and-drop),
  formulaire **par type** :
  - MCQ : 4 choix + la bonne
  - free : liste de bonnes réponses acceptées
  - closest : nombre cible
  - + preview.
- bouton **Lancer** → crée la session puis redirige vers `/host/control`.

---

## Migration depuis le seed

`getQuiz(session)` bascule de `seed-quiz.ts` (S4) vers la DB. Garder une route de
seed / import pour repeupler facilement.

---

## Checklist de validation

1. Créer un quiz avec les 3 types, sauvegarder, recharger la page → **persisté**.
2. Éditer / réordonner / supprimer des questions.
3. Lancer le quiz → la partie joue **exactement** ces questions.
4. Redémarrer le serveur → quizz toujours là (DB) ; les parties en mémoire
   repartent de zéro (normal).
5. Plusieurs quizz coexistent.
