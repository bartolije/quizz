# Audit robustesse — juillet 2026 (préparation soirée)

Audit complet (architecture + réseau + charge + UX + sécurité) réalisé le 01-02/07/2026
en vue d'une soirée d'entreprise à fort enjeu (~20-80 joueurs, wifi d'entreprise + 4G).
Constats vérifiés ligne par ligne dans le code. Ce fichier sert de **checklist de
correction** : cocher au fur et à mesure des commits.

## Verdict global

Architecture saine, code soigné. La reconnexion *participant* est bien conçue
(token localStorage, `session_restored` complet, timer ancré horloge client).
Les points faibles réels : le ré-attachement **host/TV**, le scénario **restart
serveur**, et l'absence d'**accusé de réception** des réponses.
Charge : un process Node tient 80 joueurs × 20 questions avec ≥ 10× de marge.

## P0 — correctifs avant la soirée

- [x] **Infra de tests** (préalable) : vitest + extraction `socket-handlers.ts` +
  30 tests (scoring, store, intégration Socket.io réelle). `npm test`.
- [ ] **P0-1 CRITIQUE — host/TV morts après une micro-coupure.**
  `useHostSession.ts` : `socket.once('connect', join)` → le `host_join` n'est ré-émis
  qu'à la première connexion ; or `disconnect.ts` retire le socket de `hostSocketIds`
  et des rooms. Boutons morts + TV figée, sans erreur. Fix : `socket.on` + indicateur.
- [ ] **P0-2 CRITIQUE — téléphones gelés après un restart serveur.**
  `ParticipantApp.tsx` : le listener `INVALID_TOKEN` n'est actif que quand `myId` est
  null. En pleine partie, l'erreur n'est écoutée par personne → UI figée à jamais.
  Fix : écoute permanente + purge token + message + retour /join.
- [ ] **P0-3 HAUTE — « Réponse envoyée ✓ » sans ack.**
  `QuestionPage.tsx` : emit optimiste ; une réponse émise pendant/juste avant une
  coupure est perdue en silence (le buffer part avant le rejoin → `socket.id` inconnu).
  Fix : ack Socket.io + timeout + retry + état visuel.
- [ ] **P0-4 HAUTE — resync incomplet hors question ouverte.**
  `quiz-store.ts onSessionRestored` : reconnexion pendant révélation/classement →
  vue « question » périmée figée ; si dernière question → podium jamais affiché.
  Fix : `session_restored` enrichi (lastResult, scores) + bascule de vue correcte.
- [ ] **P0-5 HAUTE — pas de vrai fallback si le wifi bloque les WebSockets.**
  `socket-config.ts` : le commentaire « polling en fallback » est faux sans
  `tryAllTransports: true` (dispo dans socket.io-client 4.8.3 installé).
  Fix + pingTimeout 5s→10s (wifi saturé).
- [ ] **P0-6 MOYENNE — payloads non bornés côté serveur.**
  Pseudo/réponse jusqu'à ~1 Mo, Levenshtein plein-matrice dessus (blocage event
  loop possible). Fix : bornes serveur + garde de longueur.
- [ ] **P0-7 MOYENNE — fin anticipée faussée + retardataires.**
  Un déconnecté sort du dénominateur « tous ont répondu » (question fermée pendant
  qu'il recharge) ; un retardataire ne reçoit pas la question en cours
  (`session_joined` sans question) et voit « Raté ❌ » sur une question jamais vue.

## Constats acceptés en l'état (contexte soirée interne)

- PIN 4 chiffres brute-forçable, pas de rate-limit join — interne, risque faible.
- `/api/sessions/:id/report` non authentifié (id = uuid non devinable).
- Comparaison ADMIN_PASSWORD non timing-safe — accessoire en interne.
- Doublon de pseudo possible avec un joueur déconnecté (rare, bénin).
- `cleanupDisconnectedParticipants` jamais appelée = **voulu** : la fenêtre de
  reconnexion est illimitée (le TTL 30 s de `socket-config.ts` est du code mort).
